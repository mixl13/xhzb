# 2026-10-29

## 排查：admin 账号登录失败（密码正确却登不进）

### 结论
登录链路（验证码 / Redis / BCrypt / Token / MySQL）**完全正常**。
问题在于 **admin 账号的密码本身不匹配**——不是系统故障。
对照实验：`ry / admin123` 登录成功并返回 token；`admin` 用任意密码均失败。

### 关键证据
- `sys_user`：admin 的 status=0、del_flag=0，账号状态正常。
- admin 密码 hash = `$2a$10$jUXh5TJxP0A04bhrmZCDOO...`，对 20 个常见密码字典做 bcrypt 离线校验均不匹配。
- `pwd_update_date` = 2025-06-13，**早于**最后一次成功登录时间 2026-05-25 → 密码在这之后没被改过，属于遗忘/输错。
- `sys_logininfor`：2026-10-29 09:42:00 / 09:42:51 两次失败（msg=用户不存在/密码错误），上次成功是 2026-05-25。
- `sys_user_role`：`ry` 无任何角色，所以不能用 ry 登录后去改 admin 密码，只能走 SQL 重置。

### 顺带发现的隐患（未修复）
- `application-dev.yml` 配了 Redis `password: 123456`，但 Redis 服务端实际**未设置密码**（AUTH 返回 `-ERR AUTH ... without any password configured`）。目前能正常读写，但配置与服务端不一致，属隐患。
- `application.yml` 的 `user.password.maxRetryCount` 已从默认 5 改为 30，`lockTime` 10 分钟。若失败次数累计到 30，`SysPasswordService.validate` 会在**校验密码之前**就抛 `UserPasswordRetryLimitExceedException`，期间即使密码正确也会被拒。

### 处理结果：已重置 admin 密码为 `admin123`

- 用 bcrypt(rounds=10, prefix=2a) 生成新哈希写入 `sys_user`，同时更新 `pwd_update_date = NOW()`。
- **旧密码哈希（如需回滚）**：`$2a$10$jUXh5TJxP0A04bhrmZCDOOGrAvj8oii7HvovUH7L8rT.jvQpgcQm2`
- 同时清理了 Redis `pwd_err_cnt:admin`。
- 验证：`admin/admin123` 登录返回 HTTP 200 + token；`getInfo` 返回 user=admin、roles=['admin']、permissions 1 条（超级管理员全权限）。整条链路打通。

## 排查方法沉淀（可复用）
用 Python 直连 Redis 读 `captcha_codes:{uuid}` 拿到验证码答案，再用同一 uuid+code 调 `POST /login`，可绕过图片识别完整复现登录流程，精确定位失败环节。

**注意**：Windows 下 Python 不认 Git Bash 的 `/tmp`，写临时文件要用 `C:\Users\<user>\AppData\Local\Temp\` 这类绝对路径；含 `$` 的哈希写 SQL 时用 `CONCAT(CHAR(36),...)` 拼接最稳妥。

注：测试过程中向 `pwd_err_cnt:admin` 写入的失败计数已清理。
